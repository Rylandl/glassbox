# Working on Glassbox

Read `docs/charter.md` first: it defines the one generic dynamics learner we
are building, the definition of done, and the rules every iteration follows.
Then read `docs/status.md`: it holds the current gap against that definition
and names the next iteration. Nothing else is required reading; git holds the
history and it is not carried forward as narrative.

Work one iteration at a time against one named gap. Freeze and commit the
harness before fitting, delete rather than deprecate, and never add a consumer
option or a platform branch. The latest user instruction overrides these
defaults. Routine work within the charter does not need another permission
question.
