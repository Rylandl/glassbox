# Command response and retained feature support

The frozen [support diagnosis](harness/online-response-support-v1.json) makes no
fits. It uses twenty saved working-v4 causal snapshots from the preceding
[forecast investigation](online-causal-trace.md). Source commit `724fc02`, artifact
identities and independent audit are recorded in [the result index](online-response-support.json).

## Command versus context

FW81 origins 156 and 157 have exactly the same learned weights. We cross their
two current commands with their two real observed histories. Past commands,
filter reconstruction and memory remain attached to their actual history.
Only the two factual pairs have observed truth; counterfactual forecasts are
compared to each other, never scored against factual truth.

Changing only command 156 to command 157 changes initial learned body-z specific
acceleration by **−321.60 / −322.88 m/s²**, and pitch acceleration by
**−502.41 / −487.82 rad/s²**, in contexts 156/157 respectively. The explicit
quadratic head accounts for −235.47 / −241.85 m/s² and
−370.77 / −368.73 rad/s². Delayed-linear features also contribute because their
past-minus-current differences depend on the current command.

| Real context | Native velocity endpoint change from command swap | 64× refined endpoint change |
| --- | ---: | ---: |
| origin156 | 0.696 m/s | 1.218 m/s |
| origin 157 | 16.726 m/s | 0.573 m/s |

Thus the large command response already exists before numerical integration;
context changes how the deployed solver amplifies it. At factual origin 157,
refinement lowers velocity error from 13.915 to 2.259 m/s but raises rate error
from 2.134 to 4.113 rad/s. Refinement is neither truth nor a general fix.

## What the retained origins identify

For each snapshot, express the existing polynomial head exactly in physical
coordinates: supported motion in physical units, raw unit gravity direction,
centered commands in declared units, delayed differences and hidden state.
Include affine terms generated by translating quadratic coordinates. The
neural head stays separate. This is algebra on the existing model, not a fit.

Each cache has 37 observed forecast origins: five bootstrap and 32 recent. Its
54-column affine design has row rank 37 at every snapshot. Consequently its
column space already spans those 37 instantaneous feature rows: after allowing
affine coefficients to change, these origins leave **zero independent rows**
that uniquely constrain the 120 quadratic coefficients per output. SVD null
components of existing coefficients have negligible response on retained rows
but can contribute large acceleration at new origins and integration stages.
An independent NumPy/SciPy audit reconstructs all 20 points; maximum normalized
retained null response is 3.56e-16.

This is numerical identifiability of the frozen origin-head design, **not** a
rank calculation for the full recursive fitting objective. Integration,
recurrent paths and other measured times can supply further constraints.
Projection magnitudes depend on the declared coordinate basis; large opposing
components must not be interpreted as separate physical forces. Ordinary
controls also have unsupported components, so this is not a validated outlier
or uncertainty detector.

The next frozen experiment, [online v6](harness/online-fit-v6.json), tests a
physical quadratic-head curvature prior on all six tapes. It prefers simpler
response where short recordings allow many equivalent head explanations,
without a vehicle-specific rule or user tuning option. It penalizes the whole
explicit quadratic head, rather than claiming to isolate an unidentified
subspace of the full dynamics.
